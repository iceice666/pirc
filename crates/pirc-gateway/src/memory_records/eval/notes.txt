# --- database and migrations (en) ---
db01 | The gateway database migrations run inside one BEGIN IMMEDIATE transaction so two processes cannot both migrate.
db02 | Schema changes go in a numbered migration file; schema.sql is always the newest whole schema.
db03 | SQLite busy errors during the WAL pragma are retried for five seconds before the gateway gives up.
db04 | secure_delete is on so forgotten memory is zeroed in the database file, not left in free pages.
db05 | Backups: copy pirc.sqlite with the sqlite3 .backup command, never cp while the gateway runs.
db06 | The old gateway.sqlite stays in the state directory untouched; the new gateway never reads it.
db07 | Foreign keys are enabled per connection with PRAGMA foreign_keys=ON; rusqlite does not do it by default.
db08 | Never hold the Db mutex across an await point; take the lock, copy the rows, drop it.

# --- database and migrations (zh) ---

zdb02 | 遷移問題：舊的 user_version 從 1 編到 1005，新資料庫用 application_id 分辨是不是自己的。
zdb03 | 備份資料庫前先做 WAL checkpoint，不然複製出來的檔案可能缺最近的寫入。
zdb04 | 資料表改名用 ALTER TABLE RENAME，SQLite 會一起改索引，但觸發器裡的參照要自己檢查。

# --- sandbox (en) ---
sb01 | The Linux sandbox uses bubblewrap; resolver sockets like nscd and systemd-resolved are hidden so DNS goes through the proxy.
sb02 | /run/WSL is hidden entirely because the interop sockets can start Windows programs outside the sandbox.
sb03 | The nix daemon socket stays reachable so nix builds work inside sessions; the daemon fetches past the proxy.
sb04 | macOS sandbox profiles are generated as SBPL strings; test them with sandbox-exec -f before shipping.
sb05 | Hard links to protected files made by the agent fail with EXDEV because the protected path is a separate mount.
sb06 | The network proxy allowlist is per session; blocked hosts answer CONNECT with 403.

# --- brain (en) ---
br01 | The brain runs one turn at a time on its own thread with a tokio LocalSet; user turns preempt wake turns.
br02 | Messages that arrive while a turn runs are merged into one steer after the debounce.
br03 | Debounce defaults to 3 seconds and is configured in brain.json under PIRC_CONFIG_DIR.
br04 | A brain turn times out after 10 minutes; the room gets a line saying it stopped.
br05 | SOUL.md and CHAT.md are read again before every turn, so edits apply on the next message.
br06 | The brain has no filesystem or shell tools; it only has gateway tools like web_search.
