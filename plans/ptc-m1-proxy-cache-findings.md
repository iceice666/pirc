# CLIProxyAPI cache investigation — public source and authorized deployment definitions

## Observed baseline stop

Baseline-001 stopped fail-closed after two valid measured trials (single-bash cold/warm), one warm-up and one cache-invalid cold trial. The second cold initial main request reported cache read 13,577 / cache creation 723 after the configured wait. All 20 physical requests had complete usage. Final conservative occupancy: **44,852,178 units / $8.9704356**, no outstanding reservation for this run. The earlier unknown request remains included at its previously approved worst-case cost. No automatic retry or marker reset occurred.

## Public implementation examined

Pinned public CLIProxyAPI commit: `d7914afdedca7af95ee974a42453dc49fc1388ce`. This is **not proof of the deployed endpoint's version/configuration**. No deployment credentials/settings were inspected and no new generation requests were made.

- [Streaming executor, lines 214–252](https://github.com/router-for-me/CLIProxyAPI/blob/d7914afdedca7af95ee974a42453dc49fc1388ce/internal/runtime/executor/claude_executor_stream.go#L214-L252): when the proxy owns cache placement and selects a Claude Code CLI fingerprint profile, ordinary non-helper requests can have missing TTL upgraded to **1h**. Explicit TTL is preserved by the upgrade helper. Native confirmed clients, helper/probe and subagent paths have distinct rules.
- [TTL upgrade and placement helpers](https://github.com/router-for-me/CLIProxyAPI/blob/d7914afdedca7af95ee974a42453dc49fc1388ce/internal/runtime/executor/claude_executor_cloaking.go#L1547-L1637): independently injects system/message cache points, handles tools fallback, upgrades only cache_control objects without an existing ttl. `shouldEnsureCacheControl` is `!confirmedClaudeCode && (cloaked || countCacheControls(payload) == 0)` at lines 1696–1698.
- [Credential fingerprint selection](https://github.com/router-for-me/CLIProxyAPI/blob/d7914afdedca7af95ee974a42453dc49fc1388ce/internal/runtime/executor/claude_fingerprint_policy.go#L92-L111): real Claude OAuth OR explicit `claude-code-cli` profile selects the CLI fingerprint. A consumer's proxy API key does not identify the upstream credential type.
- [Request transformation](https://github.com/router-for-me/CLIProxyAPI/blob/d7914afdedca7af95ee974a42453dc49fc1388ce/internal/runtime/executor/claude_executor_stream.go#L82-L109): model mapping, thinking translation and optional cloaking (system/identity/tool transformations) precede upstream execution. Our relay's exact-body equality is therefore equality **before** this external proxy, not verified post-proxy equality.
- [Routing configuration](https://github.com/router-for-me/CLIProxyAPI/blob/d7914afdedca7af95ee974a42453dc49fc1388ce/config.example.yaml#L127-L150): default example uses round-robin and disabled session affinity; optional sticky routing can fall back/rebind and share parent/child credentials. Actual deployment settings are unknown.
- [Claude usage parsing](https://github.com/router-for-me/CLIProxyAPI/blob/d7914afdedca7af95ee974a42453dc49fc1388ce/internal/runtime/executor/helps/usage_helpers.go#L1126-L1172): native Claude stream usage includes separate input, output, cache-read and cache-creation fields. Separate cross-provider translation paths can estimate input tokens ([helper](https://github.com/router-for-me/CLIProxyAPI/blob/d7914afdedca7af95ee974a42453dc49fc1388ce/internal/runtime/executor/helps/claude_input_tokens.go#L34-L48)); model-name matching alone does not establish which execution path was used.

## Authorized local deployment-definition inspection

The maintainer directed inspection to their dotfiles. Only non-secret Nix service/package definitions were read; encrypted secrets, generated runtime config, auth files and account identifiers were not opened. No dotfiles edits/build/switch/deployment or new provider calls were performed. Private host/path details are intentionally omitted here.

The package definition pins **CLIProxyAPI 7.3.15**. Its generated service configuration enables **session affinity with a 1h binding TTL**, request retry count 5, streaming bootstrap retries 2, and account-quota/usage-keeper plugins. Comments identify Claude OAuth account reserves. It does not explicitly set a Claude cache TTL, fingerprint override or cloak mode in the inspected generated block. This is intended configuration, not proof of the running binary or a particular request's selected account.

Rechecking the matching public [v7.3.15 streaming executor](https://github.com/router-for-me/CLIProxyAPI/blob/v7.3.15/internal/runtime/executor/claude_executor_stream.go#L211-L247) confirms the same conditional **1h cache upgrade**. [Fingerprint selection](https://github.com/router-for-me/CLIProxyAPI/blob/v7.3.15/internal/runtime/executor/claude_fingerprint_policy.go#L92-L111) selects CLI behavior for Claude OAuth; [wire policy](https://github.com/router-for-me/CLIProxyAPI/blob/v7.3.15/internal/runtime/executor/claude_executor_cloaking.go#L1321-L1327) defaults eligible non-native callers to cloaking. Thus an OAuth-backed request using the intended defaults has a concrete path from bare ephemeral cache markers to 1h TTL. Credential-level overrides or a different active deployment remain unverified.

**Do not conflate the two 1h values:** `session-affinity-ttl` retains account routing, not the prompt-cache TTL. The prompt TTL upgrade is executor behavior. Also, configured proxy-internal retries can create additional upstream attempts invisible to our one external HTTP-attempt ledger; complete consumer-facing usage does not establish accounting for every hidden upstream retry. A rigorous comparison needs deployment-level retry/usage provenance or an approved dedicated evaluation route.

## Consequences and next evidence needed

The public 1h-upgrade path is a concrete explanation consistent with the failed 310-second cold trial, but not a confirmed deployment diagnosis. Shared prefix refresh, credential routing and a different deployed release remain alternatives. The inspected source/config did not establish an upstream prompt-cache purge endpoint; absence in these files is not proof none exists elsewhere.

Before another paid run, obtain non-secret deployment metadata: version/commit, route/executor for the selected model, upstream credential class/profile, effective TTL, whether payload rules or cloaking transform the request, and whether credentials/cache are shared or sticky. Do not request tokens, auth files, raw prompts, or headers. Explicit `ttl:5m` is preserved by the examined helper, but changing our unchanged native adapter/wire contract is a protocol change requiring approval, not an automatic fix. No such change was made.
