## Dispatch and common policy

`agent/main.ts` → `tools/index.ts` + `features/index.ts` → `Agent` registration → destructive `restrictTools` → `toolList`/`getTool` project filtering → `toolSpecs` → provider. `invokeTool` checks current availability, hooks and auto mode; `executeTool` adds direct-call events/history. There is no central JSON-schema input validator yet. Implementations/downstream services validate inputs. M2 must split capability authority from model schemas and validate rewritten inputs without bypassing any existing checks.

All inventory rows inherit current hooks, auto-mode policy, cancellation signal and applicable write lease. `ToolResult` (`agent/tools/types.ts`) is text/image content plus optional untyped `details` and `isError`; this is a migration source, not the final typed result. `code` only admits `ptc: true`, strips images, invokes without inner direct-call events, counts completed rather than reserved calls, and inherits environment. These gaps must not be mistaken for parity.

## Registration gates and authorization

- `agent/feature.ts`: chat excludes `code`, `todo`, `background`, `agentTeam`, `goal` unless the feature's `enabled` is explicitly true. Removing the wrapper must not enable these capabilities. `features.code` disappears only at cutover.
- Browser requires its channel and feature; web search/schedules require gateway + feature. Sandbox tools require sandbox configuration + channel. Recall requires observational memory.
- `agent/capabilities.ts`: delegation maps to `delegate`/`delegation_status`; other gates cover memory search, schedules, web search. Absent flags mean allowed. Remote recall is separate.
- `agent/roles.ts`: validates syntax/count/duplicates, not registry membership. `restrictTools` silently drops unknown names today. Warn on unknown and wrapper entries in M2, no role-file/ROLE_ENTRY migration.
- `agent/main.ts`, `features/team/team.ts`: forced `TEAM_TOOL_NAMES` for teammates, inherited allowlists/project restrictions. Subagents cannot use team tools; teammate cannot spawn children. `gateway.ts`/`browser-channel.ts` deny team children; sandbox has explicit parent relay. Do not infer access from inherited environment flags.
- `daemon/agent-ops.ts`: verifies sending node's session, owner/allowed-user, operation allowlist, arguments and current workspace flags. `requireChat`, `scheduleScope`, `refuseFromScheduledRun` retain assistant-only cross-workspace and scheduled-run restrictions. `daemon/delegations.ts` rechecks approval and capabilities before dispatch. RPC smoke fakes do **not** prove these server checks.

## Current worker environment provenance (names only)

`env-allowlist.ts` filters node `process.env` (`withoutSecrets`), then `node/runner.ts` adds runner fields; `node/sandbox.ts` adds sandbox runtime fields; `agent/config.ts` merges global and trusted-project `env`; `AgentOptions.toolEnv` overlays it; `ptc/code-tool.ts` finally spreads **all** agent `process.env`, then `ctx.env`, then `PIRC_PTC=1`.

- Base allowlist: shell/path/user, locale/terminal, temp, certificate, Nix/font/toolchain names in `env-allowlist.ts`; families `LC_`, `XDG_`, `TERM_PROGRAM`, non-secret `PIRC_`.
- Operator-selected extras: `PIRC_AGENT_ENV_ALLOW`; node-level `SECRET_ENV` exclusions still apply. Config overlays are not re-filtered at PTC spawn.
- Runner fields: `PI_CODING_AGENT_SESSION_DIR`, `PIRC_WRITE_BROKER`, `PIRC_GATEWAY`, `PIRC_WORKSPACE_KIND`, `PIRC_PROJECT_TRUST`, `PIRC_PROJECT_INSTRUCTIONS`, `PIRC_WORKSPACE_MEMORY_DIR`, `PIRC_BROWSER`, `PIRC_SANDBOX`, `PIRC_SANDBOX_POLICY`.
- Sandbox: `CLAUDE_CODE_TMPDIR` plus runtime proxy additions (exact runtime names not observed).
- Children: `PIRC_PROJECT_ROOT`, `PIRC_PROJECT_TRUST`, `PIRC_TEAM_AGENT`, `PIRC_TEAM_MODE`, `PIRC_TEAM_PARENT_PID`.
- Arbitrary global/project `env` and `toolEnv` names remain unknown; no configuration contents were read. A source audit cannot prove which values are present at runtime.

QuickJS target: **no environment**, no host references, no filesystem/network/module loader. JSON arguments/results are the only bridge. Constructor chains may create realm-local functions; they must never reach a host object. Mandatory srt remains independent and fail closed.
