# Mobile and web UI audit

Status: implemented (2026-09-28, commits 26c64e4..eebe05f on top of main@94817f9). Everything below is done except web i18n and Android L7 (lint strictness, baseline profile), which were deliberately skipped, and the optional A7 near-expiry warning and A14 `setUnlockedDeviceRequired`. Nothing has been verified on a real phone yet: iOS/Android keyboard and safe areas, CJK IME in the Android composer, the terminal's new https asset origin, and the release build on poco-x7-pro still need a manual pass. W14's `directory_changed` event is opt-in (`directory=1`) because the Android event parser treats unknown types as a reset.

Findings were originally produced by two read-only reviews of `apps/web` and `apps/android`; the high-priority items were spot-checked against the source.

## Summary

Both clients are in good shape. The web app already uses `100dvh`, `env(safe-area-inset-bottom)`, `content-visibility` paging, and lazy-loads KaTeX, highlight.js, mermaid and xterm (main chunk 488 kB, 119 kB gzip). Android stores the token in the Keystore, sets `allowBackup=false`, locks the terminal WebView down, keys every `LazyColumn`, and has unit tests for the control lease and the timeline (shared golden fixtures with web).

The items below are the ones that materially change how the clients feel on a phone or that can crash the app. Effort: S (under an hour), M (half a day), L (a day or more).

## Suggested order

**Batch 1 — all S, biggest felt improvement**

- Web: W1, W3, W6 (iOS typing), W5 (icons and top safe area), W4 (side panel on narrow screens), W8 (reconnect on foreground).
- Android: A1 (crash guard), A5 (OOM on large images), A6 (upload write timeout), A8 (release cleartext), A7 (401 reason).

**Batch 2 — M, the core type-and-read loop**

- Web: W2 (soft keyboard and viewport).
- Android: A2 (text field state), A3 (delta coalescing).

**Batch 3** — everything in the medium and low lists, as time allows.
